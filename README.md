# 팀 매칭 프로젝트

1. 사이드 프로젝트를 하고 싶어하는 개발자는 많은데 어디서 팀원을 구해야할지 모름

2. 디자인 아이디어는 많은데 상품 구현을 위한 개발자를 찾고 싶은 디자이너가 많음

3. 팀을 꾸리고 싶은 대표자들에게 인력을 연결해주는 서비스가 필요함

4. 무료로 이용하는 곳

5. 실무경험을 쌓을 수 있고, 잘되면 득이 될수 있는 프로젝트를 할 수 있는 곳

## 필요 기능

1. 공고를 올릴 수 있어야 함

2. 공고를 찾을 수 있어야 함

3. 공고를 스크랩하고 문의 기능이 있어야 함

4. 공고를 통해 지원자들을 선택할 수 있어야 함

### 사용 스택

- Vite
- React
- tailwind css

- react router dom

- context Api
- zustand

- react query
- firebase

- react devuce detect

### 구현 페이지 및 기능

1. 홈페이지 -후킹 메시지와 콜투액션 버튼

   - 상단 레이아웃에 홈으로 가는 제목 버튼
   - 메뉴 버튼 및 메뉴 창

2. 로그인/회원가입

   - 콜투액션에서 버튼을 클릭하면 해당 내용에 상응하는 찾는 대상을 주소값의 parameter를 사용하여 구현
   - 개발자의 경우 디자이너와 기획자, 대표자를 찾는 경우가 많은데 콜투 액션을 선택하면 디자이너, 기획자, 대표자를 미리 선택해서 시작 가능
     **_직군별로 상아하게 적용_**

     - react-router-dom의 useSearchParams 훅으로 구현

     - 회원가입 진행시 언제라도 로그인 도리게 아래 부분에 구글 로그인이나 로그인 창 이동버튼 구현

     - 회원가입/ 로그인 폼의 인풋을 개발적인 메세지를 할당해서 특정상황에 맞게끔 정확하게 동작하는 로직 적용

     **_유저가 무엇을 해야하는지 정확하게 알려줄 수 있음_**

     - 통합회원 기능으로 팀매칭 프로젝트가 아닌 요구사항에서 로그인한 유저도 사용할 수 있도록 로그인, 회원가입등 로직이 끝나면 추가 정보를 기입하게끔 한 뒤 맞춤 페이지로 이동시킴
       ** 당 사에서 all-in-one 솔루션을 제공하는 경험을 얻을 수 있게 함**

     초기 유저 풀 확보 가능

     - 경력을 입력하기 위해 날짜를 선택할 수 있게 해둠
     - 숫자만 입력해야하는 퇴사일을 현재까지 라는 버튼을 선택하면 간단하게 처리할 수 있도록 기능 구현

3. 팀 찾기

   - 찾는 직군 별 필터 기능 제공해 맞춤 공고를 빠르게 찾을 수 있게함
   - 해당 페이지에서 바로 공고를 등록할 수 있는 버튼

4. 공고 등록

   - 회사명, 회사소개, 자격 요건등을 적을 수 있음.
   - 희망 직군 선택 가능
   - 팀원 추가를 위해 이메일로 찾기 기능 구현

5. 공고 디테일

   - 매칭 시작 버튼으로 공고를 스크랩 할 수 있음.
   - 자신의 공고는 스크랩 불가
   - 공고를 올린 사람에게 스크랩한 사람의 아이디 제공
   - 문의하기 버튼 제공
   - 공고 제목을 보고 연락드린다는 메시지를 채팅의 첫 마디로 시작하게끔 기능 구현
     **웹소켓을 사용하지 않고 파이어베이스의 실시간 리스너 기능으로 채팅 기능 구현**
   - 채팅 기능보다 팀원매칭의 필요에 집중하고자 채팅 기능은 최소한으로 구현함
     **추후 웹소켓 공부예정**

6. 채팅 기능

   - 파이어베이스 실시간 리스너로 구현
   - 대화의 창은 누구의 것인지 구분하기 위해 채팅 메시지에 본인의 아이디를 넣어둬서 구분
   - 민들어진 시점을 기록하여 쿼리에 사용하여서 순서대로 출력하도록 구현
   - 마지막 메세지에 ref를 연결랗여 메세지를 입력했을 떄 마지막 메세지가 집중되도록 구현

7. 나의 페이지

   - 내가 올린 공고

     - 해당 공고를 스크랩한 사람이 있다면 매칭을 진행할 팀원을 선택한 후 공고를 종료시킬 수 있음
     - 추후 마감된 공고를 스크랩하지 목하도록 기능 구현 예정
     - 해당 공고를 삭제하면 스크랩한 공고에도 마감처리가 되야해서 스크랩한 사람의 공고에 아이디만을 사용해 최신 데이터를 가져오도록 구현

   - 매칭 진행중인 공고

     - 버튼 클릭 시 상담 채팅 창으로 이동 구현

   - 매칭완료

     - 팀 탈퇴 기능 구현
     - 해당 공고에서 나를 제외한 팀원들은 남기도록 구현
     - 팀원들고 소통을 통해 모바일 페이지에서는 문자 기능, 전화걸기 a태그로 손쉽게 구현
     - react-device-detect를 통해 모바일 환경을 감지하게끔 하여 구현
     - android와 ios 기능구현 방법이 살짝 달랐기 때문에 마찬가지로 react-device-detect로 구현

   - 환경설정

     - 개인정보 변경
     - 개별적으로 하나씩 바로 업데이트 되도록 하나의 단위로 잘게 쪼개어서 수정기능을 구현
       **작은 단위로 서버에 전송하는것이 서버비용을 줄일 수 있다고 판단** vs 수정 내용을 전체저긍로 전달하는 것은 유저에게 수정하는 시점을 맡기면서 최종적인 결정이 났을 때만 서버교류가 이루어질수 있음, 하지만 작성 중간에 이탈 시 ㅅ새롭게 작성을 해야하는 부담이 유저에게 주어지즌 문제가 문제가 있음

          1. 페이지 구성, 하위 페이지

       3. context api/zustand

       - 다른 페이지에서도 상태 공유

       4. react query

       - 서버 데이터 관리 쿼리키로 등록
       - 캐싱을 함. 다른 페이지를 가더라도 같은 쿼리키로 등록된 데이터를 불러와야한다면 서버에 요청하는 것이 아니라 저장된 데이터를 꺼내씀. 서버에 중복 요청 안가서 서버 비용 절감 효과
       - useState(로딩 관리) + useEffect(페이지 렌더링 되는 시점에서 호출) + Error 헨들링
       - react query는 다해줌
       - sns, 매칭 등 데이터가 많이 싸인다면 홈페이지에서 모든 데이터를 가져올 필요가 있는가? 20 ~ 4,50개 정도로 제한 특정 조건을 만족할 때 다음 순서의 데이터를 가져올 수 있음 => 무한 스크롤 구현 가능
       - 추가 수정 삭제 시 => 쿼리키로 등록된 데이터가 시간이 지나서 더이상 최신이 아니라고 알려줘야 함 -> 쿼리 클라이언트로 쿼리를 무효화 처리

       ```javascript
       const queryClinet = useQueryClient();
       const chacingFn = () => queryClient.invalidateQueries({ queryKey });
       ```

       5. react 사용한 hook

          1. useState

          - 변경되는 값이 있을 때 사용
          - 인풋 -> 문자열
          - 카운터 -> 숫자
          - CRUD -> 배열 다루기
          - 회원가입 등 폼 -> 객체 다루기
          - 스위치 -> 불리언

          - useActionState, useReducer 배워두면 좋은 것들

          2. useEffect

          - firebase 실시간 리스너
          - 실시간 리스너 때문에 useEffect를 못씀

          - 일반 함수 vs 이펙트 훅
          - 일반함수는 유저가 **어떤 동작을 수행 할 때** 작동
          - 이펙트훅은 유저가 한 **행동의 결과를 토대로 작동**

          3. useRef

          - reference 참조 요소 컨트롤하는 법 (모든 html 태그, 리액트 컴포넌트)
          - useEffect로 감지 불가 실시간 업데이트가 눈에 보이지 않음 => 반응이 느림

          3-1. useImperativeRef

          - 18 버젼 ref 전달 3단계 거침
          - 19 버젼은 2단계로 줄음

          4. useMemo

          - memoization => 메모이제이션(상태 등의)변수를 메모
          - 메모리 한켠에 저장(캐싱)
          - 2번째 인자인 [] 안에 적어둔 변수, 함수가 변할 때에만 메모안의 조건을 걸어 조건에 맞을 때만 랜더링
          - 리액트 컴포넌트는 하나의 유기체로 하나라도 변뎡되면 머든 내용물들이 렌더링 됨

          5. useCallback

          - 함수를 메모 해둠
          - 4,5번 => 최적화

          6. useTransition

          - 비동기 함수랑 잘 맞음
          - 비동기 함수를 쓰는 이유-> 서버에서 지연이 있기 때문에 함수가 동작한느 시간동안 다른 UI를 보여줄 필요가 있음
          - 18버젼 까지는 비동기 함수 지원X

          7. Suspense + lazy, Loading

          - 만에 하나 리액트 컴포넌트가 너무 커서 로딩(랜더링)이 오래 걸릴 경우를 위해 로딩 창 구현
